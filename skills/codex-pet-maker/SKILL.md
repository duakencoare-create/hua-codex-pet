# Codex 桌宠制作器

把用户提供的概念或参考图转换为可安装的 Codex 动画桌宠。新项目默认输出 v2；只有用户明确要求兼容旧格式时才制作 v1。

## 开始前

确认或合理推断以下信息：

- 桌宠名称、简短描述和目录 ID；目录 ID 使用小写字母、数字和连字符。
- 视觉风格、代表性动作、必须保留的外观特征与道具。
- 参考图的使用权限；不要擅自复制第三方 Logo、受保护角色或可识别文字。
- 目标格式：新项目默认 v2；已有 8×9 图集可先保留并升级。

缺少参考图时，先根据文字生成一张完整、居中、纯色键控背景的角色基准图。此图是后续所有动画行的身份基准。

## 工作流

1. 阅读 [动画图集规范](references/animation-spec.md)，确定画布、行顺序、帧数和方向顺序。
2. 先生成基准角色图，再逐行制作动画。若环境提供 `$imagegen`，所有视觉生成都通过它完成。
3. 每一行都附上同一张基准图；一次生成完整的一行，不要让图像模型直接生成最终 8×11 图集。
4. 先完成并检查标准动画行，再制作四个方向锚点和两行连续的 16 方向注视动画。
5. 用确定性的图像处理方式切帧、透明化、统一缩放与基线，再组装最终图集。不要依赖模型精确摆放到最终单元格。
6. 按 [质量检查清单](references/qa-checklist.md) 检查结构、透明度、动作语义、身份一致性和方向连续性。
7. 生成 `pet.json`，把它与最终图集放在同一个桌宠目录中，并提供安装说明。

编写逐行动画提示词或处理人物照片时，阅读 [生成提示与身份一致性](references/prompt-guide.md)。

## 关键约束

- 单格固定为 `192×208` 像素，整张图固定为 8 列。
- v2 必须为 11 行、`1536×2288`，并在 `pet.json` 中写入 `spriteVersionNumber: 2`。
- 未使用的单元格必须完全透明；角色不能跨格、裁切或带有场景背景。
- `running` 表示 Codex 正在处理任务，不是角色向前奔跑。
- `running-right` 和 `running-left` 才是横向移动；仅在不会改变身份、文字、配饰方向或光照含义时镜像。
- 挥手、跳跃、失败等动作主要通过姿态表达；避免速度线、地面阴影、发光、漂浮符号和与角色分离的特效。
- 方向动画按屏幕坐标判断：`000` 向上、`090` 向右、`180` 向下、`270` 向左。
- 修复某个方向时，重新生成它所在的整行八帧，保持连续的动作家族；不要把风格不同的单帧补丁拼进最终图集。

## 交付结构

```text
<pet-id>/
├── pet.json
└── spritesheet.webp
```

`pet.json` 示例：

```json
{
  "id": "my-pet",
  "displayName": "我的桌宠",
  "description": "一句话说明桌宠的性格和动作。",
  "spriteVersionNumber": 2,
  "spritesheetPath": "spritesheet.webp"
}
```

只有在图集尺寸、透明度、动画语义和方向检查全部通过后，才把目录交给用户安装。不要自行上传、覆盖或删除用户现有桌宠。
